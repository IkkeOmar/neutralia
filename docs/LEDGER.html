5. Open design decisions

5.1 Leveling as power + "honor" PvP brackets — DEFERRED (2026-11-08)

Omar's direction, explicitly parked for the future:

  • Leveling can be power, not only choice. This lets different levels have different quests and different work, and creates a vertical power axis alongside the horizontal one.
  • Honor = the system restricting which levels may fight which levels (PvP brackets), and/or the PvP rank ladder. Precedent exists: WoW's old Honor rank system with battleground level brackets (10–19, 20–29, 30–39, 40–49, 50–59, 60) and rank-gated rewards; R6 Siege's Rank/Skill split with RP-based ladder and squad restrictions.

Not built yet. No design file written. Revisit when the vertical/horizontal balance is actually needed.

5.1 Engine slice — BUILT AND VERIFIED (2026-11-08)

Omar: "It looks like you've only done some front end stuff right now. That hasn't been any time into game design how to implement the 3-D stuff and how to actually have a lightweight playable game engine. I don't know what the stack will be, but you should definitely learn from the website that I reference to you earlier."

The reference was Ported2Browser / wasm.rip, from this project's earlier research. The lessons that transferred: 1. Native WASM in a browser, no plugin. Every working port ships as WASM in a tab. The original needed a downloadable plugin, and Chrome pulled NPAPI in 2014 — that killed BFH's delivery mechanism while the game ran on it. We ship no plugin. 2. Tick rate is the multiplayer contract. Counter-Strike Surf runs a browser-native Source-style recreation with ranked servers at 66 tick. We run 30 Hz + 60 Hz substeps. 3. The Emscripten route does not apply — that pattern works because ports have existing C/C++ to compile. NEUTRALIA is original. The transferable half is the architecture: WASM-ready, plugin-free, static delivery.

Built (engine/ in the repo, systems/engine-stack.md has the full decision):

Layer Choice Version Verified
Renderer Three.js, WebGL2 first 0.187.0 bundlephobia + npm
Physics Rapier 3D (deterministic build on server) 0.21.0 npm
Netcode Colyseus 0.18.12 npm + docs
Transport WebSocket now, WebTransport later — Safari 26.4 shipped WebTransport Mar 2026
Assets glTF + Meshopt + KTX2/ETC1S — 2026 benchmarks
Hosting GitHub Pages (app) + R2 (assets) + VPS (server) — CF/GH docs

Measured: - 138 KB gzipped total download (three 132.9 KB + app 4.7 KB + html 1.7 KB). BFH's own 2009 download was ~250 MB. - Integration test 29/29 — two WebSocket clients, server owns positions, movement propagates, hitscan validated, cooldown enforced, death+respawn, shared movement module bit-identical. - Browser render test 16/16 — real Chromium, real WebGL, canvas verified to contain rendered geometry, WASD movement confirmed, screenshots taken. - Visual audit passed: real 3D, third-person camera, shadows, HUD legible. - Public URL verified: HTTP 200 + WSS WELCOME through a Cloudflare quick tunnel.

Trap found and fixed: cloudflared tunnel --url loads ~/.cloudflared/config.yml by default, so its catch-all http_status:404 ingress rule applied to the quick tunnel — every request 404'd. A quick tunnel needs an explicit empty config (--config /tmp/quick-empty.yml).

Why not Unity/Godot: Unity WebGL is 7.7–10.7 MB and Godot Web export ~5 MB for an empty build. Our whole engine is 138 KB — an order of magnitude leaner, and the single-threaded choice means no COOP/COEP headers needed, so GitHub Pages works with zero header hacks.

Next: Rapier collision → Colyseus transport + lag compensation → real glTF map → animated soldier → projectile weapon → vehicles.

5.2 Vehicle system — DESIGNED (2026-11-08)

Omar asked whether the original's small vehicle roster could grow, with specialised variants per chassis. Answered: yes, and the model is Battlefield 1's, not BFH's.

BFH measured baseline: 6 chassis, 0 variants. Jeep (3 seats, 120 HP, unarmed), light tank (2 seats, 180 HP), fighter (3 seats, 190 HP), helicopter, AA gun (immobile, 250 HP), boat. Vehicles only at controlled points; 5 of 14 maps had no vehicles at all. The Jeep was on 6 maps — the most ubiquitous chassis.

Our system: 7 player-selectable chassis × 20 variants + 1 map-only emplacement. Scout car (Scout/Technical/Courier) · Armoured car NEW (APC/Carrier/Recovery) · Light tank (Javelin/Bulwark/Hunter) · Heavy tank NEW (Assault/Dug-in/Siege) · Fighter (Interceptor/Bomber/Liaison) · Helicopter (Transport/Gunship/Spotter) · Boat (Landing craft/Gunboat).

Rules (from BF2042's EA dev notes on their named failure modes — "the prevalence of explosive weaponry, and unclear combat roles across vehicles"): R1 transport carries no explosives · R2 one battlefield line per variant · R3 air does not ground-clear · R4 variant may reduce seats, never add · R5 variant chosen at spawn only · R6 anti-vehicle belongs to one chassis per domain · R7 ubiquitous chassis has the lowest ceiling.

Variants earned by playing the chassis, not by levelling — same trick as the per-weapon skill tree.

Armoured car is what makes the Engineer real — the original had no Engineer class and vehicle repair was a Gunner ability.

Rules R8 and R9 (added 2026-11-08 after a second research pass): - R8 — a variant must be worse than its chassis at something. From BF2042's Hovercraft postmortem (EA launch briefing): "We designed this vehicle to behave as an alternative to the LATV4, but not as an upgrade" — the community read it as a straight upgrade and EA cut its health in Update #2. - R9 — two variants you cannot tell apart in one sentence are the same variant. DICE on BF3: Fighter Jets and Attack Jets "were both practically the same class, with few differences" — fixed in BF4 by splitting Stealth Jets from Attack Jets with separate unlock trees.

Simulator: sim_vehicle_matrix() in tools/simulate-design.py asserts V1–V6 plus R8 (every variant has a stated weakness; every chassis has a deliberately-crippled variant), seat-economy and transport-share. It caught two real flaws on first run (contested role lines; Scout car with no predator) — both fixed in the design, not in the assertion.

Prototype: prototype/vehicles.html — 49 DOM checks, live-verified. The matrix is chassis (rows) × battlefield-line (columns), so R2 is visible in the DOM: every cell holds exactly one variant.

Docs: systems/vehicle-system.md, research/05-vehicle-variant-precedent.md, research/bfh_map_vehicles.json.

  • 2026-11-08 — THIRD BUG ROUND (1 bug, reported by Omar in playtesting, not by any test): the strafe axis was inverted. The movement code used (+cos yaw, 0, -sin yaw) for "strafe right", but a camera facing forward with up +Y has screen-right at (-cos yaw, 0, sin yaw) — the code used the negation of the true right vector, so D moved the player LEFT on screen and A moved it RIGHT. It survived because every movement test asserted only that the player MOVED, and an inverted strafe moves perfectly, just the wrong way. Fixed by building the wish direction from explicit basis vectors. New suite test/browser-direction.cjs (11 checks) asserts the SIGN of the dot product against Three.js's own camera.matrixWorld basis rather than a hand-derived formula, and was proven red by reverting the fix and rebuilding. Suite 115 -> 126 checks across seven suites; all green, direction stable 3/3 consecutive runs.

  • 2026-11-08 — SECOND BUG ROUND (5 more bugs, found by testing the rocket jump repeatedly rather than once): (1) the client's self-blast prediction was erased by reconciliation, because a blast impulse is not an input and the snapshot reset discarded it — the player launched and snapped back; (2) the projectile ray passed a direction vector 60x too long, so Rapier's reported hit distance was 60x the real one and the rocket detonated mid-flight instead of at the ground; (3) a ray starting inside the shooter's own capsule reports a zero-length hit, which detonated the rocket at muzzle height — ABOVE the centre of mass — so the blast pushed sideways instead of up; (4) removeCharacter leaked the Rapier rigid body, collider and CharacterController, so orphaned capsules piled up at the spawn point and shoved new players around (this was the real cause of both the flaky rocket jump and a movement slowdown); (5) the rocket-jump test harness used plain HTTP and could not reach an HTTPS Cloudflare tunnel, reporting "server never came up". All five are now rules in the skill. Test suite 98 -> 115 checks across six suites; the rocket-jump suite is now 19/19 and passes 5/5 consecutive runs against a clean server. Live playable at https://signature-retained-managing-replica.trycloudflare.com (ephemeral quick tunnel).
